# KAN-18 PostgreSQL/WildFly runtime evidence

runtime.json is the sanitized receipt from the successful disposable KAN-18/KAN-15 BG-06 integration run on 10–11 November 2026. The fixture applied V1 to an empty PostgreSQL database, loaded linked synthetic rows into all six business tables plus legacy sequence state, then applied V2 and V3 as schema_migrator. The legacy high-water branch selected 8000 (above the synthetic entity maximum of 7007), and cargo_app received generated ID 8001.

The receipt records server-observed session_user, current_user, current_role, and Flyway installed_by for each migration. A disposable peer on the candidate-host-access network could connect only to TCP 8080; AJP, HTTPS, management, IIOP, transaction, and direct broker listener ports were closed. Port 8080 also carries WildFly HTTP remoting, remote JNDI, and the JMS HTTP connector, so this probe establishes TCP reachability only. A follow-up protocol check showed Reader, Operator, and Administrator can look up the remote JMS connection factory and start/close a JMS connection; anonymous and invalid credentials were rejected by WildFly authentication. The client sent and consumed no messages, and database state was unchanged. Destination-level send/consume permissions remain unverified. It checks the exact five V2 index definitions, row preservation, V3 grants, protected Flyway/legacy-state privileges, role separation, application DML and DDL denials, anonymous API denial, and successful Reader, Operator, and Administrator login and protected reads. Seven-table digests and catalog/security snapshots remained unchanged across app startup, all three human reads, and restart. The callback observation schema is harness-only instrumentation and is not a product migration effect.

The app was deployed from the candidate WAR with its default META-INF/persistence.xml descriptor; the test did not substitute the H2 runtime descriptor. PostgreSQL was not published to the host. The app used a separate non-internal Docker bridge to make its localhost-only 127.0.0.1:8082 endpoint reachable. That bridge permits outbound access from the disposable app container. Cleanup removed the owned containers, networks, volume, candidate image, temporary work files, and generated secrets; no owned resources remained.

This is supplemental machine-migration and application-runtime evidence from synthetic data. It does not prove import of retained legacy data, the human denial behavior for sample seeding/reseed/ORM DDL, production migration, or external deployment. The receipt PASS means this fixture's checks passed; it does not pass any of the five BG-06 gate cases. All five remain BLOCKED pending the trusted gate evidence path. Independent pre-run and post-run reviews approved the harness and receipt.
